# PrismFlow Memory Write

在输出回复之前，判断当前对话是否产生了需要长期保留的新信息。

## 触发条件

当本轮输入或你刚完成的工作中出现以下内容时，调用 `save_memory`：

- 事实性信息，例如项目路径、版本号、环境约束、仓库位置
- 偏好性信息，例如技术栈偏好、UI 偏好、禁止项
- 关键决策，例如数据库选型、架构取舍、流程约定
- 任务结论，例如已经确认的方案、后续执行约束

## 写入规则

1. 只保存新事实，不保存已有记忆的同义复述。
2. 同一轮对话中的多条新信息，优先合并为一条完整记录再写入。
3. 写入前先自检是否已经在当前对话中保存过相同内容。
4. 保留关键细节，禁止压缩成无信息量摘要。
5. 不要边读边存；先整理，再单次写入。

## `save_memory` 内容格式

### 复杂记录

```markdown
# [主题名称]
- **核心结论**：(1句话精炼事实/判断)
- **关键细节**：
  1. (具体参数、名单、版本、日期、特定路径、配置片段)
  2. (尽量保留高保真原始数据)
- **决策/背景**：(为什么会得出这个结论)
- **后续影响**：(接下来的动作或注意事项)
```

### 简单偏好或事实

```markdown
# 偏好/事实：[简短标题]
- **记录内容**：(具体的事实描述)
- **适用范围**：(该偏好在哪些场景下生效)
```

## 质量红线

- 禁止省略关键路径、版本、日期、配置等有效信息
- 禁止使用“他”“它”“那个项目”之类模糊指代
- 每条记忆必须自包含，脱离当前对话也能独立理解

## 禁止事项

- 禁止只在回复里说“我记住了”却不调用 `save_memory`
- 禁止重复保存同一事实
- 禁止把历史检索职责混入本 skill；检索由 `memory-read` 负责

## 示例

`save_memory(content="# 偏好/事实：PrismFlowAgent 仓库位置\n- **记录内容**：PrismFlowAgent 仓库位于 D:\\ai\\code\\git-code\\PrismFlowAgent。\n- **适用范围**：后续在该仓库内执行代码修改、构建和排查时使用。", importance=3, tags=["workspace", "project_path"])`
